# 인계 중심 개선 — 2026-09-19

사용자가 제공한 교수 피드백을 바탕으로 인계의 목적을 '현장 자료와 미확인 이유를 검토하고 다음 행동을 인수하기'로 정리했다.

직접 피드백: 자료 수·핵심 내용·필수 확인 사항의 통합 요약, 재생 전 영상 길이·내용 안내, 중요 시점 바로 보기, 미확인 사유·다음 요청 전달, 선행 담당자의 입력 흐름.

팀의 설계 방향: 접힌 화면에서 핵심을 보고 펼쳐 같은 맥락의 자료를 나란히 검토한다. 교수의 직접 제안으로 귀속하지 않는다.

한 사건의 흐름: 현장 수행 → 영상 특정 시점에서 요청 작성(유형·항목·중단 이유·다음 행동) → 인계 내용 검토·요청 → 인계 검토 모드 → 통합 요약 → 요청별 근거 시점 확인 → 요청 읽음 표시 → 인수 의사 확인 → 수락 → AR로 이어받기.

요청 확인은 업무 완료와 별도이며 실제 경찰 업무 절차로 검증한 설계가 아니다. 영상은 기존 정지 이미지 기반 시간 이동 시뮬레이션이고 전송·기기 연동도 로컬 시뮬레이션이다. 임무 전후 사진 2컷은 생성 예시다.

## ③ 변경 사유를 포함한 인계 — 2026-09-21

변경 요청 카드에 변경 전·후, 지시·결정자, 결정 시각, 변경 사유, 다음 행동과 연결 영상 시점을 함께 표시한다. 발신자의 인계 작성·검토와 수신자의 인계 검토에 같은 카드를 사용한다. 발신 검토에는 현장 확인 결과도 포함한다.

요청 유형이 ‘변경 사항’이면 변경 전·후와 결정자·시각 입력란이 나타나며, 사유·다음 행동·유효한 영상 시점과 함께 입력해야 저장된다. 작성 중 값과 저장된 변경 정보는 기존 로컬 저장 방식으로 접기·새로고침·오프라인 대기 중에도 유지된다.

모든 요청(변경 내용 포함) 확인 → 인수 의사 표시 → 수락 확정 → AR로 이어받기 순서다. 수락 후 요청 확인을 취소하면 검토 대기로 돌아가며, 읽음이나 수락 자체로 현장 업무를 완료 처리하지 않는다. 이전 저장본의 기본 합류 변경 요청에는 누락된 변경 정보를 보완하고, 새 사유는 다시 확인하도록 한다. 사용자 작성 요청과 초안은 유지한다.

합류 변경과 사유는 시연 데이터다. 실제 지휘실 연동·전송이나 변경 이력 시스템의 확장은 이번 단계에 포함하지 않는다.

검증: 상태 테스트 23개, JavaScript 구문 검사, 브라우저에서 발신 검토·변경 유형 폼·확인 후 수락·확인 취소 흐름 확인.
