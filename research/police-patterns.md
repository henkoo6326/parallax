# PARALLAX — 경찰 맥락의 디자인 시스템 사양

조사일 2026-09-13. 원본 `original-screen-design.html` 16화면을 검토했다. 아래 **제품 원칙**은 제공된 문서에 근거하고, **공식 기준**은 링크의 원문, **제안**은 이번 리서치의 설계 판단이다. 법률 준수·현장 안전·기관 정책을 인증하는 문서가 아니다.

## 가장 중요한 결론

PARALLAX의 차별점은 AI 비서나 관제 대시보드가 아니라 **기록의 범위와 출처를 이어 주는 인수인계 도구**다. 아름다움은 이 차이를 즉시 알아보게 하는 질서에서 나와야 한다. '남은 구역'에 위험·실패·개인 성과를 암시하는 색이나 순위를 붙이지 않는다.

원문이 활동 중 화면을 표시하지 않는다고 선언하면서 뛰면서 조작하는 장면을 묘사하는 것은 미해결 충돌이다. 새 시스템은 **활동 전 준비 / 활동 중 비시각 기록 / 활동 후 검토**를 기본 경계로 삼고, 이동 중 커버 조작 허용 범위는 실제 운영 검증 과제로 명시한다. 면담·진술 분석은 이 16화면 범위에 없으므로 추가 기능으로 확장하지 않는다.

## 1. 세 가지 축을 섞지 않는다 — 제품 원칙 + 제안

| 축 | 필수 정보 | 잘못된 결합 |
|---|---|---|
| 관찰·기록 | 기록된 위치·시각·방향·조건, 남은 구역 | 기록됨 = 안전함 |
| 전달 | 기기 저장 / 전송 대기 / 서버 확인 / 수신자 확인 | 업로드됨 = 인계 완료 |
| 출처·책임 | 장치·발신자·원본 시각·변환 여부 | AI 전사 = 경찰이 확인한 진술 |

이 세 축은 별도 텍스트 라벨로 유지한다. 녹색 체크 하나로 '기록 정상·안전·전송·인계 완료'를 통합하지 않는다.

## 2. 구성요소 계약 — 자체 권고

| 구성요소 | 필수 필드 | 상태와 상호작용 | 연결 화면 |
|---|---|---|---|
| 출처 라벨 | 발신/획득 주체, 원본 시각 | 사람이 지정함·장치에서 연결함·전사 변환을 구별. 세부 출처로 이동 | A-0~3, A-5, A-7, B-2~4 |
| 기록 상태 띠 | 현재 기록 여부, 장치, 경과시간 | 기록 대기 / 기록 중 / 중단 / 연결 확인 필요. 화면에서 숨겨지는 활동 단계의 신호는 별도 검증 | A-0, A-4, B-6 |
| 전송 상태 행 | 로컬 저장 여부, 대기 건수, 마지막 확인 시각 | 대기→전송 중→서버 확인. 실패는 자료 보존 여부+복구 행동을 함께 표기 | A-6, A-8, B-5 |
| 지도 범례 | 원문 5상태, 문구·패턴·경계선 | '남은 구역'은 팀 전체 기준. 공간순 정렬. 위험도/점수 없음 | A-3, B-3 |
| 연결 자료 카드 | 원본 장치, 촬영 시각, 위치 연결 상태 | 썸네일 실패·위치 연결 안 됨·자료 접근 불가 구분 | A-7, B-4 |
| 전사 검토 블록 | 원본 음성, 타임코드, 전사문 | 사람이 수정한 부분과 원본을 구분. 불명확 부분을 추측으로 채우지 않음 | A-5 |
| 인수인계 확인 | 인계 대상, 자료 범위, 열람 이력 안내 | 전송 확인과 명시적 수락을 분리. 중복 탭으로 중복 인계 생성하지 않음 | A-8, B-0, B-5 |
| 사람 발신 메시지 | 발신자, 발신 시각, 내용 | 지휘실 지시 / 동료 발신. 시스템 위험 판정과 구분 | A-2, A-6 |

## 3. 타이포그래피와 터치

**공식 기준.** 웹 WCAG 2.2 AA 일반 텍스트 4.5:1, 큰 텍스트 3:1; 의미 있는 비텍스트 UI 요소는 적용 범위에서 3:1. WCAG 2.5.8은 예외를 포함한 24×24 CSS px 최소 타깃이며, 48 dp라는 뜻이 아니다. Android Compose 접근성 문서는 최소 터치 영역 48 dp를 설명한다. 네이티브 dp·sp와 브리핑 HTML의 CSS px를 구분한다.

- [WCAG 2.2 규범](https://www.w3.org/TR/WCAG22/)
- [일반 텍스트 대비 해설](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- [비텍스트 대비 해설](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- [최소 타깃 해설](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- [Android Compose 접근성 기본값](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)

**자체 권고.** 핵심 조작 56 dp, 보조 조작 최소 48 dp, 인접 독립 타깃 간 8 dp 여유. 본문 16–18 sp, 사건 핵심 정보 22–28 sp, 시각/출처 14 sp부터 검토. 핵심 현장 텍스트 7:1 대비를 목표로 삼되 이것만으로 실외 가독성이 보장되지는 않는다. 장갑·젖은 화면·야간·직사광은 실제 기기 테스트가 필요하다. 접수 코드·주소·시각을 말줄임표로 숨기지 않는다. 시간·건수는 tabular numerals, 본문 한글은 시스템 산세리프. 장식적 대문자·좁은 자간은 기능 라벨에 쓰지 않는다.

## 4. 폴더블 — 하나의 과업이 이어져야 한다

**공식 문서 요지.** Android는 FoldingFeature로 자세·접힘 경계를 읽어 레이아웃을 조정하는 방법을 제시한다. 고정 기기 모델만으로 배치하지 않고 창 크기와 자세를 함께 다뤄야 한다. 아래 수치/배치 정책은 PARALLAX 제안이지 Android의 필수 수치가 아니다.

[Android fold-aware 가이드](https://developer.android.com/develop/adaptive-apps/guides/foldables/make-your-app-fold-aware)

**자체 권고.** 접힘에서는 단일 과업, 펼침에서는 지도–자료 또는 원문–전사 같은 연관 두 패널. 힌지 위에는 핵심 버튼·문장을 놓지 않는다. 접고 펼칠 때 사건, 선택 구역, 지도 뷰, 재생 시점, 검토 수정문, 전송 상태가 유지되어야 한다. 왼쪽 목록에서 고른 항목을 오른쪽에서 보다가 접으면 선택 항목 상세가 남는다. 펼침이 새 업무 단계 시작을 뜻하지 않는다. 가로 방향 강제나 반접힘 자동 확정은 금지한다.

## 5. 알림의 위계

**공식 패턴.** GOV.UK는 배너를 절제하고, 현재 과업과 직접 연관된 정보는 본문에 두며, 입력 검증 오류는 오류 요약/필드 오류로 안내한다. 오류 요약에서 각 문제 필드로 이동할 수 있어야 한다. 이는 참고 패턴이며 경찰 앱의 의무 규정이 아니다.

- [GOV.UK notification banner](https://design-system.service.gov.uk/components/notification-banner/)
- [GOV.UK error summary](https://design-system.service.gov.uk/components/error-summary/)

**자체 권고.** 일반 상태는 영구 상태 행, 사람 발신 지시는 발신자 포함 메시지, 입력 문제는 해당 필드, 기록 손실/실패는 복구 동작과 함께 인접 표시한다. '위험도 색상 금지'가 모든 오류 신호 금지를 뜻하지는 않는다. 기술적 실패의 색을 쓰더라도 대상이 '기록 중단'임을 문구·아이콘으로 한정하고 공간 위험 표현으로 전용하지 않는다. 인계 완료처럼 중요한 상태를 잠깐 사라지는 토스트만으로 전달하지 않는다.

[WCAG 상태 메시지 해설](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): 포커스 이동 없이 표시하는 상태 메시지는 보조기술로도 인지 가능해야 한다. 잦은 지도 업데이트까지 모두 긴급 알림으로 읽어 주지 않는 것은 자체 권고다.

## 6. AI·전사·출처

**공식 패턴.** Carbon AI label은 AI가 관여한 부분을 표시하고 설명으로 진입하는 일관된 통로를 제공한다. 장식이나 AI 실행 버튼으로 쓰지 않는다고 설명한다.

[Carbon AI label](https://carbondesignsystem.com/components/ai-label/usage/)

**PARALLAX 적용.** 제품 전체에 AI 반짝임을 붙이지 않고 변환된 전사 블록에만 '음성 전사'를 붙인다. 설명에는 입력 자료·변환 범위·원문 열기·수정 이력을 둔다. 모델 신뢰도 숫자를 사실 정확도처럼 제시하지 않는다. AI 요약·중요 장면 추천·피의자 위험 추정·면담 진실성 판정은 현 문서 범위를 벗어난다. 사람의 북마크는 '지휘실 북마크'로 직접 표시한다.

## 7. 신뢰를 해치는 원문 표현 수정

| 원문 또는 가능 오독 | 제안 | 이유 |
|---|---|---|
| 남은 구역 = 확률이 몰려 있는 곳 | 기록 범위 밖이며 안전 여부를 뜻하지 않습니다 | 탐색 이론을 실내 AR에 적용하려면 별도 모델 검증이 필요. 제품의 판단 금지와도 충돌 |
| 투명 = 안전 | 투명도와 관계없이 범례·패턴·상태 문구 제공 | 지도 관례는 맥락마다 달라 단정 불가 |
| 청록이라 모든 색각/실외 문제 해결 | 대비 측정+패턴+실기 검증 | 색상 하나로 가독성을 보증할 수 없음 |
| 성과평가·인사·감찰에 쓰이지 않습니다 | 기관 정책으로 확정된 사용 목적과 접근 범위를 표시 | 설계 의도와 실제 정책·시스템 보장을 혼동하지 않음 |
| REC | 위치 기록 중 / 연결된 영상 / 음성 전사 중을 구분 | 서비스가 자체 촬영하는 것으로 오해하지 않게 |
| 인계 완료 | 전송 완료 / 수신자 확인 / 인계 수락 각각 표시 | 통신 성공과 사람이 받은 사실을 혼동하지 않음 |

## 8. 다음 제작 단계의 검증 기준 — 자체 제안

1. 단 한 번의 확인으로 현재 사건·기록 상태·마지막 동기화 시점을 정확히 설명하는지 측정한다.
2. 기록된 구역을 안전 구역이라고 해석하는 참가자가 나오면 지도 표현을 수정한다.
3. 네트워크를 끊고 복귀한 뒤 로컬 저장·미전송·서버 확인 상태를 구분하는지 확인한다.
4. 펼침→접힘→펼침에서 선택/입력/재생/전송이 유실되거나 중복되지 않는지 검증한다.
5. '원본', '변환', '사람 확인'을 구분하고 전사 오류를 원문에서 찾아 수정할 수 있는지 확인한다.
6. 큰 글자, 화면낭독기, 키보드 포커스, 색각 모의, 주·야간과 장갑 조건을 각각 확인한다.
7. A 사용자에게 남은 구역이 노출되지 않고 B 인수인계 맥락에서 팀 전체 기준으로 전달되는지 확인한다.

실제 경찰 대상 관찰/사용성 결과를 얻기 전에는 '현장 검증 완료', '안전 확보', '법적 증거성 보장'이라는 문구를 쓰지 않는다. 이번 문서는 설계 기준이며, 운영·보존·접근·녹음 범위의 기관 정책은 별도 확정 사항이다.
