# UI 아카이브 조사 — 2026-09-13

사용자 제공 original-screen-design.html의 16개 화면을 먼저 읽고, 로컬 자료를 외부 업로드하지 않고 일반 패턴명만 검색했다. 서비스 UI는 제작하지 않았다.

## 확인 범위

UIbowl에서 실제 실행한 패턴: 지도뷰·내주변, 녹음하기, 제어, 알림, 초대하기·받기, 라이브·플레이어. 각 필터의 공개 스크린샷을 브라우저로 관찰했다. 지도 검색창의 지도 입력 후 패턴 체크박스를 사용했으며, 이후 같은 공개 패턴 URL 구조와 화면에 실제 존재하는 패턴명을 사용했다. 무료 버전은 최신 3개의 패턴만 확인할 수 있다는 안내를 확인했다. 이는 전체 아카이브 전수조사나 멤버십 내부 열람을 뜻하지 않는다.

직접 확인한 8개 레퍼런스 행 중 daglo의 두 행은 같은 흐름의 서로 다른 상태이다. 따라서 8개 독립 앱으로 계산하면 안 된다. 상세 기록은 references.json 참조.

## 경찰 서비스로 번역한 핵심

1. 지도 소비자 앱에서 빌릴 것은 지도와 목록의 연결, 현재 위치로 복귀, 필터 적용 범위이다. 가격 경쟁 핀이나 추천순을 남은 구역에 적용하면 시스템 우선순위 추천처럼 오해된다.
2. 전사 앱에서 빌릴 것은 원문·시간·재생구간의 대응이다. AI 요약 생성은 원문을 서식에 옮긴다는 PARALLAX의 경계를 넘는다.
3. 기기 앱의 연결 안내는 상태+즉시 가능한 행동으로 축약한다. 매 인계마다 온보딩을 반복하면 안 된다.
4. 알림의 읽음과 지시 확인, 전송 시도와 상대 수신, 로컬 저장과 서버 동기화를 혼합하지 않는다. 소비자 앱의 간단한 완료 toast는 경찰 현장에서 영속 상태로 보강해야 한다.
5. 초대·받기 검색의 차봇은 시각적으로 깔끔해도 인계의 책임 범위를 표현하지 못한다. 배제 근거도 연구 성과다.
6. 랭플릭스의 동기 자막은 유용하지만 스와이프만으로 구간 이동하는 제스처는 장갑·한손 조건에서 명시 버튼으로 바꿔야 한다.
7. Refero Styles는 토큰을 역할·금지 규칙과 함께 설명하는 문서 구조만 빌린다. 그 문서의 수치를 실제 앱 실측이나 경찰 표준으로 인용하지 않는다.

## 접근 한계

Mobbin은 직접 웹과 브라우저 접근 모두 상단 내비게이션 외 본문이 비어 개별 앱 확인 실패. Refero Audio player transcript 검색은 로그인 요구. Refero Styles Visitors 토큰 문서는 공개 접근 성공. Page Flows는 검색 색인에 Turo/Causal 흐름 목차 확인 가능하나 직접 페이지 403. Screenlane 직접 403. 로그인·결제·우회 없이 공개 자료만 사용했다.
