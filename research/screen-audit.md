# PARALLAX 16화면 요소 감사

분석 원본: `research/original-screen-design.html` (사용자 제공 화면설계 사본). 원문 화면 ID와 이름을 그대로 유지한다. 원문은 기획 의도를 확인하는 1차 자료지만 그 안의 외부 표준·신제품·실측 수치는 별도 원문 검증 전까지 근거로 재사용하지 않는다. 아래 개선은 디자인 시스템 제안이며 앱 화면 구현이 아니다.

## 보존할 제품 원칙

- 대상은 일반 소비자가 아니라 현장 경찰과 후속 인수인계자다. 활동 전 준비 → 활동 중 화면 OFF → 활동 후 기록 검토/인계라는 업무 리듬이 우선이다.
- 남은 구역은 후속 B 트랙에서 처음 보인다. 개인의 누락·성과·활동 순위를 만들지 않는다. 구역 상태는 팀 기준, 전달과 접근 이력은 책임 주체를 확인하는 별도 기록이다.
- 시스템이 위험, 중요성, 확인 우선순위를 판정하지 않는다. 사람의 지시와 출처, 원문, 시간, 관찰 범위를 보존한다.
- 접힘은 핵심 결정, 펼침은 비교·검토, 반접힘은 착용 확인의 후보 자세다. 접힘 각도나 제조사명이 화면 전환의 유일한 조건이 되어서는 안 된다.

## 기존 설계의 토큰·논리 문제: 외형 개선 전 수정

1. 원문의 4열 산식은 내부 폭 626pt에 들어가지 않는다. 24×2 + 120×4 + 32×2 + 중앙 64 = 656pt. 중앙 회피대를 32로 해석해야 624pt이며 '±32'와 다르다. 더구나 가로 펼침을 설명하면서 626×890pt라고 적고 와이어 비율은 626/446이다. 특정 기기 수치 기반 확정 그리드를 폐기하고 가용 창 폭, 인셋, 실제 힌지 영역을 입력으로 쓰는 적응형 토큰으로 제안해야 한다.
2. 120pt 장갑 타깃은 모든 UI의 정답이 아니다. 실기 장갑·터치센서·손 크기·행동 위험도가 검증되지 않았다. 핵심 행동을 큰 필드 타깃으로 연구하되 dp/pt/CSS px/mm를 혼용하지 말고 플랫폼 기본 최소와 현장 후보를 구분한다.
3. 원문 '0.1lx 자동 테마 전환, 사용자가 고르지 않음'은 센서 접근/급변/상황 제어 문제가 있다. 주간 고대비 기본과 저조도 모드 후보, 명시적 사용자 선택, 자동 전환 시 상태 보존을 디자인 시스템에서 정의한다. 표준의 적용 범위 검증 없이 '경찰 앱 다크모드는 위반'을 단정하지 않는다.
4. '남은 구역 = 확률이 몰려 있는 곳', '최우선 처리 대상'은 추천 금지 원칙과 충돌한다. 로봇 비용 상수와 탐색확률은 경찰의 실제 위험/우선순위로 번역할 수 없다. 사용자 화면에는 관측 기록의 범위와 공백만 표시한다.
5. A-7의 '우리가 촬영하지 않는다'와 A-5 폰 AR 백업 캡처는 표현 충돌이다. 기록 좌표 서비스/외부 영상 연결/선택적 백업 캡처의 데이터 역할을 구분해 설명해야 한다.
6. '항목이 넘치면 줄이지 화면을 늘리지 않는다'는 중요한 인계 정보 생략 위험. 핵심 요약은 고정하되 나머지 상세는 명시적으로 접근 가능해야 한다. 글자 확대 때 콘텐츠를 잘라서는 안 된다.
7. 원문에 반복되는 '아이콘 우선·던져 숨김·가장자리 리사이즈'는 소비자 OS 패턴이다. 경찰 현장에선 텍스트 라벨과 버튼 대체 경로, 고정 프리셋을 우선 제안한다.

## 공통 컴포넌트 구조 제안

- Context Header: 사건 ID + 사건명 + 범위/층 + 출처 + 최신 변경 시각. 접힘에도 핵심 맥락 유지.
- Provenance Label: 기록 출처, 사람이 한 지시, 변환된 전사, 동기화 상태를 서로 다른 라벨 체계로. 배지 없음=사실 확정이라는 추론 금지.
- Action Stack: 주 행동 1개, 보조 행동, 분리된 취소. 터치영역과 시각 무게를 독립 정의.
- Zone State: 5개 업무 상태 + 별도 데이터 상태(미수신/오래됨/위치 불확실). 업무 상태와 동기화 상태 혼합 금지.
- Readiness Row: 연결/기록 준비/배터리/장비 조건. A-4와 B-6 공유.
- Record Item: 시각/장소/출처/원문/변환·수정 이력. A-5/A-7/B-4 공유.
- Handoff Receipt: 패키지 버전/발신/수신/포함 자료/진행 상태/확인 시각. A-8/B-0/B-5 공유.
- Privacy Shield: 즉시 화면 가림과 인증 복귀. 가림은 기록 삭제/중단과 독립이며 실제 보안 정책 필요.
- Empty / Loading / Stale / Offline / Permission / Failed: 16화면 모두 상태 매트릭스를 가지며 빈칸을 '안 봄/자료 없음/문제 없음'으로 해석시키지 않음.

## 검증 질문과 후보 통과 기준

검증 수치 목표는 아직 실측 결과가 아니라 연구 후보로 표기한다. 현직 경찰 참여로 장갑·한 손·강한 조명·저조도·소음·통신 저하 조건에서 (1) B-0 열람과 B-5 수락 구분, (2) B-3 남은 구역과 조건 미흡/미수신 구분, (3) 접고 펴도 선택 구역·재생 위치·인계 상태 보존, (4) 발신 대기와 인수 완료 구분, (5) 음성 원문과 전사 수정 구분을 확인한다. 오판 시 색상보다 문구·상태 모델·위계를 먼저 수정한다.
